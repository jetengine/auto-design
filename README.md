# AI Agent 通过 MCP 驱动 CATIA 三维建模原理

> **执行范式**：自然语言需求 → 工具调用 → CATIA 原生特征 → 检查证据 → 迭代修复

---

## 1. 概述

本系统通过 **Model Context Protocol（MCP）** 将大语言模型 AI Agent 与 **CATIA V5** 原生建模内核连接，实现"用自然语言描述几何需求，由 Agent 自动完成可编辑特征树建模"的闭环工作流。

核心目标：

- **可编辑**：产出保留完整参数、引用关系与特征历史的 `CATPart`，而非死几何。
- **可验证**：每一步都有原生 API 返回的结构化证据（更新状态、几何度量、STEP 回读）。
- **可复现**：请求 ID 幂等、强类型工具、单 STA 串行 COM，避免脏状态。
- **可迭代**：失败时 Agent 拿到真实原因，自动规划修复而不是盲试。

## 3. 分层职责

### 3.1 用户自然语言需求

| 维度       | 说明                                               |
| ---------- | -------------------------------------------------- |
| 几何与参数 | 尺寸、公差、材料、坐标系、参考基准                 |
| 特征树结构 | 命名规范、父子关系、草图/特征分组                  |
| 验收与格式 | 交付文件（`.CATPart` / `.STEP`）、检查项、报告口径 |

### 3.2 AI Agent — 理解与任务编排

- **拆分建模步骤**：将需求分解为 Sketch → Pad → Fillet → Surface … 的原子操作序列。
- **选择 MCP 工具**：根据能力探测结果匹配 53 个工具中的正确签名。
- **根据反馈修复**：解析 CATIA 返回的失败原因（草图欠约束、拓扑冲突、更新失败等），生成修复动作。

### 3.3 MCP 协议层（STDIO / JSON-RPC）

- **类型化请求**：每个工具有 JSON Schema，参数在传输前即校验。
- **结构化返回**：几何度量、特征 ID、状态码、错误详情均为结构化字段。
- **请求 ID 幂等**：相同请求 ID 不会重复创建特征，保障可重试。

### 3.4 CATIA Agent MCP — 固定、强类型工具集

- **能力与版本探测**：启动握手时暴露 CATIA 版本、许可模块、可用工具清单。
- **参数与路径校验**：文件路径、单位、坐标系在进入 COM 前预检。
- **53 个建模/分析工具**：覆盖 Part Design、GSD、Assembly、Analysis、测量与导出。
- **单 STA 串行 COM**：所有调用在单一 STA 线程排队，避免 CATIA COM 的并发崩溃。
- **安全保存与回读**：写盘后立刻重新打开或 STEP 回读校验。

### 3.5 Windows COM（Automation / ROT）

- 通过 **Running Object Table** 获取已启动的 CATIA 活动会话。
- 调用 CATIA Automation API（`Application`、`Documents`、`Part`、`HybridBody`…）。
- 返回**真实几何/特征状态**，而非脚本执行日志。

### 3.6 CATIA V5 原生建模内核

- **Part Design**：Sketch、Pad、Pocket、Shaft、Rib、Fillet、Draft …
- **GSD 曲面**：Spline、Sweep、Loft、Fill、Blend、Join、Close Surface …
- **Assembly**：装配约束、发布几何、上下文引用。
- **Analysis**：质量特性、干涉、连续性、几何度量。
- **原生特征树**：所有产出都是可编辑节点，保留参数与父子引用。

## 4. 反馈闭环内容

每次工具调用后，MCP 层返回给 Agent 的结构化证据至少包含：

- 特征更新状态（成功 / 失败 / 需要更新）
- 特征树增量（新增 / 修改的节点 ID 与名称）
- 关键尺寸、公差、几何度量
- 失败原因（草图欠约束、拓扑无效、引用丢失、许可不足…）

Agent 据此进行 **"检查证据 → 迭代修复"** 循环，直到几何满足验收标准。

---

## 5. 安全边界

- **不开放任意 COM / 脚本执行**：仅暴露白名单工具，禁止 `CATScript` 注入或任意宏。
- **实时文件验证**：写入前后校验路径、扩展名、单位制、命名冲突。
- **超时与状态检查**：每个工具设最大执行时长，卡死时中断并回收 STA。
- **只读探测优先**：能力/状态查询工具无副作用，可自由调用。

## 6. 原生建模价值

| 关注点   | 传统"脚本喷 STEP" | 本方案（原生特征）                                      |
| -------- | ----------------- | ------------------------------------------------------- |
| 可编辑性 | 死几何，无参数    | Sketch/Pad/Spline/Loft/Fill/Join/Close Surface 全部保留 |
| 参数复用 | 无                | 参数、约束、引用关系完整保留                            |
| 变更传播 | 需要整体重建      | 修改父节点，子特征自动更新                              |
| 工程审查 | 只能看结果几何    | 可读的特征历史，便于审查与协作                          |

---

## 7. 工程验证原则

> **命令返回 ≠ 几何合格**

即使 COM 调用返回成功，也必须继续做几何层验证：

1. **更新检查**：整棵特征树 `Update`，确认无红叉。
2. **间隙 / 干涉**：Assembly 场景下检查 Clash & Clearance。
3. **连续性**：G0 / G1 / G2 分析，防止拼接曲面隐性缺陷。
4. **单一实体**：布尔与 Join 后确认无孤立体、无碎面。
5. **STEP 回读**：导出 `.STEP` 后重新导入并做体积/表面积比对。

只有全部通过，才把 `CATPart` + `STEP` + 验证报告作为交付物交出。

---

## 8. 工程交付物

- **可编辑特征树**：`.CATPart`（保留全部参数与历史）
- **中性格式**：`.STEP`（用于下游 CAM/CAE 或第三方评审）
- **视图 / 报告**：截图、测量表、验证清单、失败-修复日志

---

## 9. 关键设计取舍

- **强类型 > 通用脚本**：牺牲灵活性换取可预测性和安全性。
- **单 STA 串行 > 并发**：CATIA COM 不是线程安全的，串行是唯一稳态。
- **证据驱动 > 乐观执行**：每步都要有原生 API 证据，禁止假设成功。
- **原生特征 > 直接建 B-Rep**：保住工程可编辑性是首要价值。
